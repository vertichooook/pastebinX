# Architecture

1. **Schema:** PostgreSQL users, entries, sessions, login_limits and audit_logs. Entry uniqueness is per user, never global. UUIDs identify objects; a CHECK constraint binds slug to def_number. Audit identifiers survive deletion, deliberately without cascading foreign keys.
2. **Authentication:** bcrypt cost 12; only seeded admin creates accounts. Passwords accept 12–72 bytes. Login errors do not distinguish unknown, blocked or wrong-password accounts. Fixed 15-minute attempt windows are stored in PostgreSQL, separately by username (10) and source IP (40).
3. **Sessions:** random 256-bit opaque token; only SHA-256 digest stored in PostgreSQL. Absolute expiry 8 hours. HttpOnly, SameSite=Strict, Secure in production. Active status checked on every request; password changes, blocking and deletion revoke sessions. Session creation locks the user row and rechecks the password hash to serialize with revocation.
4. **Numbering:** transaction atomically updates the user's next_def_number with RETURNING, inserts the previous counter value as defN, and writes audit. PostgreSQL serializes updates to that user row. Failed insert rolls back counter. Deletion never decrements it.
5. **Authorization:** ownedEntry always selects by session user ID AND slug AND active AND non-expired. Client-supplied user_id never influences ordinary entry lookup. API never returns other users' entries. Admin endpoints check a fresh server session and role. Admin entry mutations match both UUID and selected user ID.
6. **Admin:** configurable ADMIN_PATH, users and individual cards, text creation/edit/deactivation/deletion, password reset, blocking, audit viewer. Administrators cannot modify or delete admin accounts through this interface, avoiding accidental lockout. Admin credentials can be rotated by an explicit maintenance operation; seed never overwrites an existing password.
7. **Routing:** Next.js dynamic catch-all resolves only /defN or the configured admin route and recognized child paths. Root, /login, /admin, malformed and unknown paths return HTTP 404. Valid /defN renders login before authentication and resolves only the current user's entry afterward. Responses are private and no-store; missing, expired, deleted and inaccessible entries have the same 404.

CSRF uses a signed expiring double-submit token before login, then a token in the server session. Every mutation also requires exact configured Origin. Content is rendered by React as text; no HTML rendering. Security headers restrict frames, objects, forms and connections. Next.js hydration currently requires inline scripts; CSP is defense in depth, not a replacement for text escaping. No passwords, hashes, cookies, session tokens or text bodies are written to audit or application logs.

TRUST_PROXY defaults false. Enable it only if the application is reachable exclusively through a proxy which replaces X-Forwarded-For, such as the provided Nginx configuration. The Compose port binds to loopback and PostgreSQL has no published port.
